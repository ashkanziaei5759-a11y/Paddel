# وصل‌کردن درگاه پرداخت

راهنمای کامل اتصال درگاه بانکی به پرشین پدل.

---

## ۱. اول این را بخوانید: شاپرک مستقیم نمی‌شود

خیلی‌ها فکر می‌کنند باید مستقیم به «شاپرک» وصل شوند. این‌طور نیست.

**شاپرک** شبکه‌ی پرداخت بانکی کشور است و مستقیماً به کسب‌وکارها سرویس نمی‌دهد.
شما به یکی از این دو راه وصل می‌شوید:

### راه الف — درگاه واسط (PSP غیربانکی) ← **پیشنهاد من**

شرکت‌هایی مثل **زرین‌پال**، **زیبال**، **نکست‌پی**، **آیدی‌پی**.

| | |
|---|---|
| زمان راه‌اندازی | چند ساعت تا ۲ روز |
| نیاز به شرکت ثبت‌شده | ❌ با کد ملی هم می‌شود |
| کارمزد | حدود ۱٪ (سقف دارد) |
| تسویه | روزانه یا هفتگی |

**این کد از هر سه‌شان پشتیبانی می‌کند و آماده است.**

### راه ب — درگاه مستقیم بانکی

از بانک ملت، سامان، پارسیان و… .

| | |
|---|---|
| زمان راه‌اندازی | ۲ هفته تا ۲ ماه |
| نیاز به شرکت ثبت‌شده | ✅ اجباری |
| نیاز به نماد اعتماد | ✅ معمولاً اجباری |
| کارمزد | کمتر |

اگر این راه را می‌خواهید، پس از گرفتن مستندات بانک، یک فایل جدید در
`src/lib/payments/` بسازید (از `zarinpal.ts` الگو بگیرید) و در
`src/lib/payments/index.ts` ثبتش کنید. ساختار کد برای همین جدا نوشته شده.

---

## ۲. پیش‌نیازهای درگاه واسط

قبل از ثبت‌نام آماده داشته باشید:

- ✅ **سایت بالا و در دسترس** با دامنه‌ی واقعی (`https://persianpdl.ir`)
- ✅ **SSL فعال** — بدون https هیچ درگاهی تأیید نمی‌کند
- ✅ کد ملی یا شناسه‌ی شرکت
- ✅ شماره **شبا**ی حساب برای واریز
- ✅ شماره موبایل به نام خودتان
- ✅ صفحه‌ی «تماس با ما» و «قوانین و مقررات» روی سایت

> ⚠️ **اول سایت را بالا بیاورید، بعد ثبت‌نام کنید.** کارشناس درگاه سایت شما
> را باز می‌کند و اگر بالا نباشد، رد می‌شوید و باید از نو شروع کنید.

## ۳. راه‌اندازی زرین‌پال (نمونه)

### گام ۱ — ثبت‌نام

1. به [zarinpal.com](https://www.zarinpal.com) بروید و حساب بسازید
2. شماره موبایل و ایمیل را تأیید کنید
3. احراز هویت: کد ملی + شبا

### گام ۲ — ساخت درگاه

از پنل: **درگاه پرداخت ← درگاه جدید**

| فیلد | مقدار |
|---|---|
| نام کسب‌وکار | باشگاه پدل پرشین پدل |
| آدرس سایت | `https://persianpdl.ir` |
| دسته‌بندی | ورزشی / خدمات |
| توضیحات | رزرو آنلاین زمین پدل و مدیریت باشگاه |

### گام ۳ — آدرس بازگشت (Callback)

این مهم‌ترین فیلد است. اگر جایی خواست، **دقیقاً** این را بگذارید:

```
https://persianpdl.ir/api/payments/callback
```

> 💡 برنامه خودش `paymentId` را به انتهای این آدرس اضافه می‌کند. شما فقط
> همین آدرس پایه را ثبت کنید.

### گام ۴ — گرفتن Merchant ID

پس از تأیید (چند ساعت تا ۲ روز)، یک شناسه‌ی ۳۶ کاراکتری می‌گیرید:

```
xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

### گام ۵ — تنظیم در برنامه

روی سرور، فایل `C:\PersianPadel\.env` را باز کنید:

```ini
PAYMENT_PROVIDER=zarinpal
ZARINPAL_MERCHANT_ID="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
ZARINPAL_SANDBOX=false
```

ذخیره و ری‌استارت:

```powershell
Restart-Service PersianPadel
```

## ۴. درگاه‌های دیگر

همان مراحل، فقط متغیرها فرق می‌کنند.

### زیبال
```ini
PAYMENT_PROVIDER=zibal
ZIBAL_MERCHANT="کد-مرچنت-شما"
```
> برای آزمایش می‌توانید `ZIBAL_MERCHANT="zibal"` بگذارید — حالت تست خودشان است.

### نکست‌پی
```ini
PAYMENT_PROVIDER=nextpay
NEXTPAY_API_KEY="کلید-شما"
```

## ۵. آزمایش پیش از افتتاح

### الف) آزمایش با مبلغ کم و پول واقعی

بهترین آزمون، یک پرداخت واقعی است:

1. با یک حساب بازیکن وارد شوید
2. کیف پول ← شارژ ← **۱۰٬۰۰۰ تومان**
3. پرداخت را کامل کنید
4. باید به سایت برگردید و موجودی اضافه شده باشد

### ب) بررسی در پایگاه داده

```powershell
$env:PGPASSWORD='رمز-پایگاه-داده'
psql -h 127.0.0.1 -U padel_app -d persian_padel -c "SELECT status, amount, ""providerRef"", ""paidAt"" FROM payments ORDER BY ""createdAt"" DESC LIMIT 5;"
```

وضعیت باید `SUCCESS` باشد و `providerRef` پر.

### ج) آزمون انصراف

یک پرداخت را شروع کنید و در صفحه‌ی بانک **انصراف** بزنید. باید:
- به سایت برگردید
- پیام «پرداخت لغو شد» ببینید
- موجودی **تغییر نکند**

### د) آزمون دکمه‌ی بازگشت مرورگر

پس از پرداخت موفق، دکمه‌ی Back مرورگر را بزنید و صفحه را دوباره لود کنید.
**موجودی نباید دو برابر شود.** این حالت با کلید یکتای تراکنش محافظت شده،
ولی خوب است خودتان هم ببینید.

## ۶. چطور این کد از پول محافظت می‌کند

اینها را برای اطمینان خودتان بدانید:

**۱. هرگز به فرانت‌اند اعتماد نمی‌شود.**
مبلغ از روی چیزی که مرورگر می‌فرستد تعیین نمی‌شود. سرور مبلغ را خودش ثبت
می‌کند و هنگام تأیید، مبلغِ برگشتی از درگاه را با آن **مقایسه** می‌کند. اگر
یکی نباشد، شارژ انجام نمی‌شود.

**۲. شارژ فقط پس از تأیید سمت سرور.**
بازگشت کاربر از درگاه به‌تنهایی هیچ پولی جابه‌جا نمی‌کند. برنامه مستقیماً از
سرور خودش به درگاه وصل می‌شود و می‌پرسد «این تراکنش واقعاً موفق بود؟».

**۳. یک پرداخت، فقط یک شارژ.**
هر تراکنش یک «کلید یکتا» دارد. اگر آدرس بازگشت ده بار صدا زده شود، فقط یک
بار شارژ می‌شود.

**۴. مهلت روی تماس با درگاه.**
اگر درگاه کند شود یا جواب ندهد، درخواست بعد از مهلت مشخص با پیام روشن تمام
می‌شود. بدون این، هر کاربری که از درگاه برمی‌گشت یک اتصال سرور را برای همیشه
می‌گرفت و با چند نفر، کل اپ می‌خوابید.

**۵. درگاه آزمایشی در محیط واقعی مسدود است.**
اگر `PAYMENT_PROVIDER=mock` بماند، برنامه در حالت production خطای روشن
می‌دهد و پرداخت را اجرا نمی‌کند.

## ۷. رفع اشکال

### «درگاه پرداخت باشگاه هنوز پیکربندی نشده است»

`PAYMENT_PROVIDER` هنوز `mock` است یا کلید درگاه خالی است. `.env` را درست
کنید و `Restart-Service PersianPadel` بزنید.

### «مبلغ تأییدشده با مبلغ درخواستی مطابقت ندارد»

**این محافظ است، نه اشکال.** یعنی مبلغی که درگاه برگرداند با آنچه ثبت شده
فرق دارد. تقریباً همیشه به این دلیل است که درگاه مبلغ را به **ریال** می‌خواهد
ولی شما **تومان** فرستاده‌اید (یا برعکس). کد داخلاً همه‌چیز را ریال نگه می‌دارد.

### پول کم شد ولی کیف پول شارژ نشد

1. جدول `payments` را ببینید — وضعیت آن تراکنش چیست؟
2. لاگ را ببینید: `Get-Content C:\PersianPadel\logs\app-error.log -Tail 50`
3. اگر وضعیت `FAILED` است ولی بانک پول را کم کرده، معمولاً تا ۷۲ ساعت خودکار
   برمی‌گردد. در پنل درگاه هم قابل پیگیری است.
4. برای جبران دستی: پنل مدیریت ← کاربران ← افزایش موجودی

### به سایت برنمی‌گردد

آدرس بازگشت را در پنل درگاه بررسی کنید. باید **دقیقاً** این باشد و با
`https` شروع شود:
```
https://persianpdl.ir/api/payments/callback
```

### درگاه می‌گوید «سایت در دسترس نیست»

- آیا `https://persianpdl.ir` از بیرون باز می‌شود؟ (نه فقط از داخل سرور)
- آیا گواهی SSL معتبر است؟
- آیا فایروال هاست پورت ۴۴۳ را باز گذاشته؟
