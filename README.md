## معرفی

پرشین پدل یک PWA کامل برای اداره‌ی یک باشگاه پدل است: رزرو زمین با تقویم شمسی،
کیف پول و درگاه پرداخت ایرانی، سطح‌بندی بازیکنان، سیستم امتیاز، تورنومنت‌های
لیگ و گروهی‌+حذفی، انتخاب پارتنر، و یک پنل مدیریت کامل.

اپلیکیشن روی **iPhone، Android و دسکتاپ** اجرا می‌شود و می‌تواند روی صفحه‌ی اصلی
نصب شود؛ بدون هیچ وابستگی به App Store یا Google Play.

## قابلیت‌ها

### بازیکن
| بخش | توضیح |
|---|---|
| ثبت‌نام و ورود | نام کاربری + رمز عبور، تأیید شماره موبایل با کد یک‌بارمصرف |
| رزرو زمین | تقویم شمسی، انتخاب زمین، مشاهده‌ی ساعات آزاد، رزرو چند سانس پشت‌سرهم |
| کیف پول | مشاهده‌ی موجودی، شارژ از درگاه بانکی، تاریخچه‌ی کامل تراکنش‌ها |
| لغو رزرو | محاسبه‌ی خودکار مبلغ بازگشتی و واریز فوری به کیف پول |
| پروفایل | سطح، امتیاز، موجودی، تاریخچه‌ی حضور و تورنومنت‌ها |
| تورنومنت | مشاهده‌ی مسابقات، انتخاب پارتنر، جدول، براکت و نتایج |
| اعلان‌ها | درخواست پارتنر، تأیید رزرو، بازگشت وجه، دریافت امتیاز |

### مدیر
مدیریت کاربران و سطوح · مدیریت زمین‌ها و قیمت‌گذاری زمانی · مدیریت رزروها و
لغوها · کیف پول و امتیاز کاربران · ساخت و اداره‌ی تورنومنت‌ها · ثبت نتایج و
اعطای خودکار امتیاز · گزارش مالی.

## معماری

```
Next.js 15 (App Router) · React 19 · TypeScript
Tailwind CSS 3 · PostgreSQL 16 · Prisma 6
احراز هویت: نشست امضاشده‌ی JWT + رکورد پایگاه داده (کوکی HttpOnly)
```

چرا این پشته؟ رندر سمت سرور برای بارگذاری سریع روی موبایل، یک پایگاه کد واحد
برای فرانت و بک، تراکنش‌های اتمیک پستگرس برای عملیات مالی، و استقرار ساده روی
هر پلتفرم Node.

مستندات کامل معماری و شمای پایگاه داده: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md)

## راه‌اندازی

### پیش‌نیازها
Node.js ۲۰ به بالا · PostgreSQL ۱۴ به بالا

### گام‌ها

```bash
# ۱. نصب وابستگی‌ها
npm install

# ۲. تنظیم متغیرهای محیطی
cp .env.example .env
#   DATABASE_URL و AUTH_SECRET را پر کنید
#   تولید کلید امن:  openssl rand -base64 48

# ۳. ساخت جداول پایگاه داده
npx prisma migrate deploy      # یا در توسعه:  npm run db:migrate

# ۴. داده‌ی اولیه (مدیر، سه زمین، بازیکنان نمونه، یک تورنومنت)
npm run db:seed

# ۵. اجرا
npm run dev                    # توسعه
npm run build && npm run start # تولید
```

اپلیکیشن روی <http://localhost:3000> بالا می‌آید.

### حساب‌های پیش‌فرض پس از اجرای seed

| نقش | نام کاربری | رمز عبور |
|---|---|---|
| مدیر | `admin` | `Admin@12345` |
| بازیکن | `ali`، `sara`، `reza`، … | `Player@12345` |

> این مقادیر را پیش از استقرار در محیط واقعی حتماً تغییر دهید.

## متغیرهای محیطی

| متغیر | توضیح |
|---|---|
| `DATABASE_URL` | نشانی اتصال PostgreSQL |
| `AUTH_SECRET` | کلید امضای نشست — حداقل ۳۲ کاراکتر تصادفی |
| `SESSION_TTL_DAYS` | طول عمر نشست (پیش‌فرض ۳۰ روز) |
| `APP_TIMEZONE` | منطقه‌ی زمانی باشگاه (پیش‌فرض `Asia/Tehran`) |
| `OTP_PROVIDER` | `console` (توسعه) یا `kavenegar` |
| `OTP_TTL_SECONDS` | اعتبار کد تأیید (پیش‌فرض ۱۲۰ ثانیه) |
| `PAYMENT_PROVIDER` | `mock` \| `zarinpal` \| `zibal` \| `nextpay` |
| `NEXT_PUBLIC_APP_URL` | نشانی عمومی اپ (برای بازگشت از درگاه) |

در حالت توسعه کد تأیید به‌جای پیامک در **کنسول سرور** چاپ می‌شود و
`PAYMENT_PROVIDER=mock` یک درگاه شبیه‌سازی‌شده در `/payment/mock` فراهم می‌کند.

## اسکریپت‌ها

```bash
npm run dev         # سرور توسعه
npm run build       # ساخت نسخه‌ی تولید
npm run start       # اجرای نسخه‌ی تولید
npm run typecheck   # بررسی نوع‌ها
npm run db:migrate  # ساخت و اعمال مهاجرت
npm run db:deploy   # اعمال مهاجرت‌ها در تولید
npm run db:seed     # داده‌ی اولیه
npm run db:studio   # مرورگر پایگاه داده
```

## امنیت

- رمز عبور با **bcrypt** (۱۲ دور) هش می‌شود؛ کد OTP نیز هرگز خام ذخیره نمی‌شود.
- نشست‌ها هم امضای JWT دارند و هم رکورد قابل‌ابطال در پایگاه داده.
- محدودسازی نرخ برای ورود، ثبت‌نام، ارسال OTP، پرداخت و رزرو.
- قفل موقت حساب پس از تلاش‌های ناموفق پیاپی.
- کنترل دسترسی مبتنی بر نقش در تمام مسیرهای مدیریتی.
- **هیچ مبلغی از سمت کلاینت پذیرفته نمی‌شود**؛ قیمت‌گذاری، کسر و بازگشت وجه
  تماماً سمت سرور محاسبه می‌شود.
- تأیید پرداخت همیشه از طریق فراخوانی مستقیم درگاه انجام می‌گیرد و مبلغ
  تأییدشده با مبلغ درخواستی مقایسه می‌شود.
- عملیات کیف پول و امتیاز درون تراکنش اتمیک و با قفل ردیف (`SELECT … FOR UPDATE`)
  اجرا می‌شود؛ کلید یکتای هر عملیات از اجرای دوباره جلوگیری می‌کند.
- جلوگیری از رزرو هم‌زمان با محدودیت یکتای `(courtId, startsAt)` در پایگاه داده.

## قوانین بازگشت وجه

| زمان باقی‌مانده تا شروع | کسر |
|---|---|
| بیشتر از ۴ ساعت | ۰٪ |
| بین ۲ تا ۴ ساعت | ۱۵٪ |
| بین ۱ تا ۲ ساعت | ۲۵٪ |
| بین ۳۰ دقیقه تا ۱ ساعت | ۳۰٪ |
| کمتر از ۳۰ دقیقه | ۵۰٪ |

این پله‌ها در جدول `cancellation_policies` نگه‌داری می‌شوند و توسط مدیر قابل
تغییرند. مبلغ باقی‌مانده به‌صورت خودکار به کیف پول بازمی‌گردد و در تاریخچه ثبت می‌شود.

## توسعه‌ی آینده

ساختار پایگاه داده از هم‌اکنون آماده‌ی افزودن این بخش‌هاست:

- **فروشگاه امتیازی** — جدول‌های `store_products`، `store_orders` و دفتر کل
  امتیاز (`points_transactions`) موجودند.
- **Push Notification و پیامک** — مدل `Notification` دارای فیلد `channels` است و
  لایه‌ی ارسال از لایه‌ی ایجاد جداست.
- **درگاه‌های پرداخت تازه** — کافی است رابط `PaymentGateway` پیاده‌سازی و در
  `src/lib/payments/index.ts` ثبت شود.
- **زمین‌های بیشتر** — تعداد زمین‌ها در هیچ جای کد ثابت نشده است.
